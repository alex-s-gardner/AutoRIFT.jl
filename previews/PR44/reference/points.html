Points and grids ​

A PointSet gives the points where a pass measures and, for each point, the chip size, the search radius and the displacement to search around. Build one to vary those fields across the scene; autorift's scalar keywords cannot.

AutoRIFT.PointSet Type
julia
PointSet{N}

Where to correlate, and with what geometry. Fields are N-dimensional arrays of matching shape, one entry per search center. The constructor throws DimensionMismatch if the shapes differ.

PointSet{1} holds scattered centers at arbitrary coordinates; PointSet{2} holds centers on a grid. Correlation treats the two identically, but the multi-chip-size search requires PointSet{2} because its filtering steps use neighborhoods.

Fields

  • x, y: center coordinates in image pixels, Float64. Fractional coordinates are allowed: x = 10.5 sits between columns.

  • radius_x, radius_y: search half-extent per axis, in pixels; the search window spans 2 * radius. A point with either radius zero is skipped.

  • dx_prior, dy_prior: a-priori displacement in pixels. The search window is centered on the prior rather than on zero.

  • chip_size_x, chip_size_y: chip extent in pixels, per point. A gridded multi-chip-size search overwrites these at each level; they take effect on a scattered PointSet{1}.

  • chip_size_min_x, chip_size_max_x: the range of chip sizes (x extent, in pixels) at which a point may be searched. A level runs at a point only when its chip size lies within the range. 0 means unbounded and is the default. The finest level ignores these bounds and attempts every point with a positive radius.

  • positioned: false marks a point whose x, y are a placeholder, such as a geogrid point outside the image footprint, which is given an arbitrary coordinate and a zero radius. Defaults to true. It does not affect whether a point is searched (AutoRIFT.issearchable tests the radius alone). Blocked processing uses it to exclude placeholder coordinates when sizing a block's read window.

Each field has its own type parameter, because a field is an AutoRIFT.Uniform exactly when it was given as a scalar, and fields may be mixed.

See also pointset, gridpoints, npoints.

AutoRIFT.pointset Function
julia
pointset(x, y; kwargs...) -> PointSet

Build a PointSet from center coordinates, filling unspecified geometry from scalar defaults.

x and y are arrays of the same shape: vectors for scattered points, matrices for gridded ones. pointset(xy; kwargs...) takes a single vector of (x, y) tuples, and pointset(idx; kwargs...) a vector of CartesianIndex{2}, read as (row, col) = (y, x). Each geometry keyword accepts a scalar, applied to every point, or an array matching the shape of x. A fractional value for an integer field throws ArgumentError, and a mismatched shape throws DimensionMismatch.

julia
julia> pts = AutoRIFT.pointset([10.0, 50.5, 200.0], [20.0, 60.0, 30.25];
                               search_radius = 25, chip_size = 32);

julia> AutoRIFT.npoints(pts)
3

julia> pts.x[2], pts.radius_x[2], pts.chip_size_x[2]
(50.5, 25, 32)

Keywords

  • search_radius = 25: half-extent of the search window, an AutoRIFT.Extent. A scalar means square; (X = …, Y = …) names the axes.

  • chip_size = 32: chip extent, likewise.

  • search_radius_x, search_radius_y, chip_size_x, chip_size_y: per-axis overrides of the extents above. Unlike an extent, they accept a per-point array.

  • dx_prior = 0.0, dy_prior = 0.0: a-priori displacement, a scalar or per-point array.

  • chip_size_min_x = 0, chip_size_max_x = 0: the chip sizes at which a point may be searched. 0 means unbounded. A scalar or per-point array.

  • positioned = true: whether each coordinate is a real image position. A scalar or per-point array. See PointSet.

AutoRIFT.gridpoints Function
julia
gridpoints(imagesize, spacing; kwargs...) -> PointSet{2}
gridpoints(xs, ys; kwargs...) -> PointSet{2}

Build a gridded PointSet: centers on a regular lattice laid out in 2-D, as the multi-chip-size search requires.

The first form places centers every spacing pixels (an AutoRIFT.Extent or scalar) across an image of size imagesize = (nrows, ncols), inset from the edges so that a chip and its search window fit. It throws ArgumentError if spacing is not positive or no center fits. The second form takes explicit coordinate vectors; rows of the result vary with ys and columns with xs.

julia
julia> pts = AutoRIFT.gridpoints((512, 512), 32; chip_size = 32, search_radius = 25);

julia> ndims(pts), size(pts)
(2, (14, 14))

Accepts the same geometry keywords as pointset.

AutoRIFT.npoints Function
julia
npoints(pts::PointSet) -> Int

Number of search centers, including those skipped for a zero search radius. See nsearchable for the number that will be correlated.

source
AutoRIFT.nsearchable Function
julia
nsearchable(pts::PointSet) -> Int

Number of points with a non-zero search radius in both axes, which are the points that will be correlated.

Can be much smaller than npoints, because the coarse pass zeroes the radius wherever it found no coherent motion.

source
AutoRIFT.issearchable Function
julia
issearchable(pts::PointSet, i) -> Bool

Whether point i has a positive search radius in both axes. A window with no extent in one axis cannot yield a displacement.

source
AutoRIFT.scatter Function
julia
scatter(pts::PointSet) -> PointSet{1}

View a PointSet as a flat list of points, discarding the grid layout. Each field is vec of the original, so the result shares memory with pts: mutating either is visible in the other.

source
AutoRIFT.rebuild Function
julia
rebuild(pts::PointSet; kwargs...) -> PointSet

A PointSet with the named fields replaced. Fields not named are shared with pts, not copied. The keywords are the field names of PointSet; the replacements must have matching axes.

source
AutoRIFT.sanitize! Function
julia
sanitize!(pts::PointSet, min_radius) -> Int

Normalize search radii in place and return the number of points left searchable. Two rules, from the reference (autoRIFT.py:547-551):

  1. A point whose radius is non-positive in either axis is unsearchable, so both of its radii are set to zero.

  2. Every other point gets at least min_radius in each axis, since a correlation surface only a few pixels across cannot support sub-pixel refinement. Points zeroed by rule 1 stay zero.

source
AutoRIFT.chip_bounds Function
julia
chip_bounds(pts::PointSet, i) -> (rows, cols)

Pixel ranges of the chip cut from the secondary image at point i.

The chip is centered on floor(x - dx_prior) and floor(y - dy_prior), so the search begins where motion is expected. Its extent is chip_size_y rows by chip_size_x columns, from c - h to c + h - 1 with h = chip_size ÷ 2.

source
AutoRIFT.search_bounds Function
julia
search_bounds(pts::PointSet, i) -> (rows, cols)

Pixel ranges of the search window cut from the reference image at point i.

The window is centered on floor(x) and floor(y), without the prior. It is larger than the chip by the search radius: it extends radius pixels before the chip's first index but only radius - 1 after its last, giving a width of chip + 2 * radius - 1. Correlating the chip against it yields a surface of (2 * radius_y, 2 * radius_x) samples with zero displacement on a sample. A symmetric window would give an odd-sized surface whose center is half a sample from zero displacement.
