Results ​

autorift on plain arrays returns a MultichipResult: the displacement layers, the correlation strength, and the chip size that produced each point. The rest of this page covers the steps behind it, for callers who run a single chip size or resample a field themselves.

AutoRIFT.MultichipResult Type
julia
MultichipResult

Displacement over the full grid, assembled from all chip-size levels.

dx, dy, correlation, and peak_ratio are as in DisplacementField. chip_size records which level produced each point (0 where none did), and interpolated marks points filled from their neighbors rather than measured.

peak_ratio measures whether the displacement was unique, where correlation measures how strong the match was. Gate on correlation and use peak_ratio to diagnose an ambiguous surface; see Judging a result.

At an interpolated point peak_ratio is the median over the neighborhood the displacement was taken from, and correlation is NaN.

peak_ratio is zero where the correlation peak lay against the search boundary. The displacement there is a lower bound, and any positive threshold excludes the point. Select these points with peak_ratio .== 0 to find where search_radius is too small.

chip_size holds the level's x extent, which identifies the level since the aspect is constant across levels. It indicates how much spatial averaging is behind each estimate.

interpolated is a BitMatrix, whereas searched on DisplacementField is a Matrix{Bool}, because interpolated is written only by the single-threaded merge.

AutoRIFT.DisplacementField Type
julia
DisplacementField

Per-point results of a correlation pass.

dx and dy are displacements in pixels, correlation the peak similarity, peak_ratio the ratio of that peak to the best rival peak elsewhere on the surface (see AutoRIFT.peak_ratio), and searched marks the points that were correlated. Points that were not searched, or that failed, are NaN in dx/dy and false in searched, which distinguishes no measurement from a measurement of zero.

correlation and peak_ratio measure different things: the first is how strong the match was, the second whether it was unique. A peak of 0.6 with no rival locates a displacement; the same 0.6 with a second peak of 0.58 a wavelength away does not say which of the two the feature moved by.

searched is a Matrix{Bool} rather than a BitMatrix because threaded tasks write neighboring points, and writes to elements sharing a packed word can be lost.

Fields have the shape of the PointSet they came from, so a gridded point set yields gridded output.

AutoRIFT.track! Function
julia
track!(out, pair, pts, p; subpixel = first(p.subpixel), measure = first(p.similarity))
    -> DisplacementField

Correlate pair at every searchable point of pts, writing into out.

The chip is cut from the secondary image and the search window from the reference, so the returned displacement is the offset from secondary back to reference, which is the negative of the feature motion (see peak_offset). It is not negated here.

Keywords:

  • subpixel: the refinement method, overriding the parameter set's first. A coarse pass uses integer peaks only.

  • measure: the similarity measure, overriding first(p.similarity). p.similarity has one entry per chip-size level, so the chip-size loop passes the right one.

  • geometry: the largest chip and radius, overriding those derived from pts. Correlating a subset of a point set with the geometry of the whole gives the same answer as correlating the whole and reading those points out (see AutoRIFT.PassGeometry). It may widen the pass but not narrow it, otherwise ArgumentError is thrown.

  • okmask: the pixels valid in both images, default valid of the pair. Pass it when correlating the same pair repeatedly to compute it once. It must equal valid(pair); a narrower mask silently skips points.

Throws DimensionMismatch if out and pts differ in length.

A point is skipped, leaving NaN, if its search radius is zero in either axis, if its chip or search window falls outside the image, if no more than min_chip_valid_fraction of its chip is valid, or if its chip is constant. Padding is not data, so a chip made mostly of padding is not correlated.

AutoRIFT.correlate_multichip Function
julia
correlate_multichip(pair, grid, p) -> MultichipResult

Correlate pair over grid at every chip-size level, finest chip first.

grid must be a gridded PointSet, since the coarse pass decimates it and the merge resamples between levels. Its chip_size_x field is ignored: the level sets it.

Each level runs chipsize_level and contributes only where no finer level already succeeded, so the smallest chip that yields a coherent estimate wins at every point.

pair is the filtered pair. AutoRIFT.correlate_tiled runs the same loop over an unfiltered one, filtering per block.

source
AutoRIFT.chipsize_level Function
julia
chipsize_level(pair, grid, p, chip_size, wanted) -> Union{Nothing,NamedTuple}

One chip-size level: a coarse pass to find where motion is coherent, then a fine pass restricted to that neighborhood, then hole filling. Callable on its own to run one chip size without the loop.

Returns (; field, filled), the displacement field and the linear indices that were filled from neighbors rather than measured. Returns nothing if the coarse pass validated less than min_coarse_valid_fraction of the grid, or found nothing worth continuing.

chip_size is an AutoRIFT.Extent; a scalar means square. wanted marks the points this level should attempt, which in the level loop are those no finer level resolved. measure and subpixel are this level's similarity measure and refinement method (see measure_at). They are positional because p.similarity and p.subpixel are tuples with one entry per level, and the subpixel refinement factor depends on the level's chip size.

prior_dx/prior_dy are the finer levels' answer over grid, from which a decimated level fills its own holes before interpolating back up (see AutoRIFT.correlate_multichip). Without them holes are filled from the level's own neighbors alone, which is correct for a level run in isolation.

phase is grid's sub-pixel phase as (x, y), to which a decimated level snaps its coarse nodes. nothing computes it from grid; a caller running several levels over one grid can compute it once with AutoRIFT._grid_phases.

pair is the filtered pair. A blocked run uses the AutoRIFT.PassRunner form instead.

source
AutoRIFT.PassGeometry Type
julia
AutoRIFT.PassGeometry

The largest chip and search radius any point in a pass uses, as two AutoRIFT.Extent fields: chip and radius.

These bound the pass rather than describe every point. A point is correlated at its own radius rounded up to a rung of the AutoRIFT.RADIUS_BUCKET_RUNGS ladder and clamped to radius, so the pass uses one transform length per bucket its points reach. chip is uniform within a level.

A different transform length changes correlation by about 1e-7 and, rarely, moves a displacement by one refinement step. A point in the topmost bucket is correlated at the maximum radius of its point set, which is smaller for a subset than for the whole set. To make a subset reproduce the whole set's answer, pass the whole set's geometry to track!; it may widen the pass but not narrow it.

Build one with AutoRIFT.pass_geometry.

reject_outliers(dx, dy, radius_x, radius_y, valid, upsampling, method) -> BitMatrix

Which displacements to keep, per method, an OutlierMethod.

AutoRIFT.relax Function
julia
AutoRIFT.relax(method::OutlierMethod) -> OutlierMethod

A looser variant of method for a decimated grid.

The coarse pass runs on a strided subset, so a point's neighbors lie further away and resemble it less. Holding them to the fine pass's standard would reject coherent motion. What loosening means is the method's own: GardnerFilter drops one iteration (minimum one), and NoOutlierFilter returns itself.

source
AutoRIFT.rescale Function
julia
AutoRIFT.rescale(method::OutlierMethod, oversample, stride = 1) -> OutlierMethod

method with its neighborhood matched to a grid posted oversample times finer than its chip.

When the grid spacing divides the chip size, adjacent points share most of their imagery. At chip_size = 16 and grid_spacing = 8, a point's 5x5 neighborhood spans two chip widths. The reference applies two corrections (autoRIFT.py:484-505), which GardnerFilter implements:

  • The window widens to (window - 1) * oversample + 1, so it spans the same ground as at one point per chip.

  • The agreement fraction rises to frac * (1 - overlap) + overlap^2, where overlap is the fraction of a neighbor's chip shared with the center's, because overlapping chips agree partly by seeing the same pixels.

stride is the coarse pass's decimation, which reduces the overlap because decimated neighbors sit further apart. Pass it for the coarse filter and leave it at 1 for the fine filter. oversample < 1 throws ArgumentError; oversample == 1 returns the method unchanged. NoOutlierFilter returns itself.

Separate from relax: relax handles a decimated grid and this handles a grid finer than its chips. A run can need either, both or neither.

For a Landsat pair over Jakobshavn at chip_size = 16, grid_spacing = 8, the unscaled 5-wide filter at 0.32 agreement scores a 0.916 speed correlation against the ITS_LIVE granule, and the rescaled filter scores 0.996.

Resampling ​

AutoRIFT.resample Function
julia
resample(A, dstsize, method) -> Matrix

Resample A to dstsize, ignoring NaN.

method is Nearest, Area, Bilinear, or Bicubic. A destination sample with no valid contributor is NaN.

Coordinates use the half-sample convention: destination sample i maps to source position (i - 0.5) * scale + 0.5, so the two grids cover the same extent with no half-sample offset.

scale is the source samples per destination sample, per axis, and defaults to the size ratio. Pass it when the sizes do not determine the correspondence. A source taken as every stride-th sample of the destination has a scale of exactly 1/stride, but the size ratio cld(n, stride) / n equals that only when stride divides n; otherwise it drifts, reaching a full cell of offset at the far edge.

source
AutoRIFT.resample! Function
julia
resample!(out, A, method; scale) -> out

In-place resample, to the size of out.

AutoRIFT.Nearest Type
julia
Nearest()

Nearest-neighbor resampling: each destination sample takes the value of the source sample containing its center. Use it for a mask, where an interpolated value between two categories is meaningless. See resample.

source
AutoRIFT.Area Type
julia
Area()

Area-averaging resampling: each destination sample is the mean of the source samples its footprint covers, weighted by overlap and ignoring NaN. Use it to decimate a measured field, where a point sample would discard most of the data. See resample.

source
AutoRIFT.Bilinear Type
julia
Bilinear()

Bilinear resampling: the weighted mean of the surrounding 2-by-2 neighborhood, ignoring NaN. Use it to decimate a quantity whose fractional part matters, such as one about to be rounded or taken to a ceiling. See resample.

source
AutoRIFT.Bicubic Type
julia
Bicubic()

Bicubic resampling: a smooth interpolant over the surrounding 4-by-4 neighborhood. Use it to upsample a displacement field into a prior, where nearest-neighbor would leave visible seams. See resample.

Mask operations ​

AutoRIFT.dilate_within Function
julia
dilate_within(mask, radius) -> BitMatrix

Every position strictly closer than Euclidean radius to a true in mask.

Used to grow the coarse pass's validity mask before it restricts the fine search. radius is in grid cells and the distance is Euclidean, not chessboard (a chessboard ball of radius 8 has 40% more area).

The comparison is strict, matching the reference's distance_transform_edt(!MC) < BuffDistanceC (autoRIFT.py:709). At the default radius of 8, positions at distance exactly 8 are the axis-aligned ones eight cells out. Admitting them widens the searched region by 72 coarse cells on the golden Landsat case, which is 30,084 fine points the reference leaves unsearched.

The distance is exact, computed by the two-pass squared-distance transform of Felzenszwalb & Huttenlocher (2012), which is separable and O(n) per row and column.

source
AutoRIFT.small_components Function
julia
small_components(mask, minsize) -> BitMatrix

Positions in a connected component of mask holding fewer than minsize trues.

Components are eight-connected, so two positions touching only at a corner belong to one component, as in the reference's connectivity=2 (autoRIFT.py:1652). Under four-connectivity a diagonal pair of holes would be two components of one position, and the size test would give a different answer.

This selects which holes in a displacement field are interpolated across, regardless of shape. An L-shaped four-position hole, for example, has positions with too few neighbors to pass a neighbor count.

minsize is exclusive, matching bwareaopen(image, size1)'s size < size1: at minsize = 5 components of one to four positions are returned and a five-position component is not.

One union-find pass over the array (union by size, full path compression), so the cost is effectively linear.
