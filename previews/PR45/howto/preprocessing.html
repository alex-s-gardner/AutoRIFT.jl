Choosing a preprocessing filter ​

Correlation compares brightness patterns. A different sun angle, a gain change, haze or a sensor artifact changes brightness without the ground moving, and the correlator has to see past it. Preprocessing removes that before the comparison.

One keyword selects the filter, by symbol or by instance:

julia
autorift(reference, secondary; preprocess = :highpass)        # the default
autorift(reference, secondary; preprocess = Highpass(; width = 11))

Why the default is not :none ​

The similarity measure already removes some of this. ZNCC subtracts the mean and divides by the standard deviation of each chip, so a uniform brightening or a gain change is invisible to it. It cannot absorb variation within a chip, and a gradient across the scene is that kind of variation.

Here is a pair where the secondary image carries an illumination gradient the reference does not:

julia
using AutoRIFT
include("../../figures.jl")  # plotting helpers and the example scenes; see [Plotting](@ref)
using Statistics: median, quantile

reference, clean, truth_dx, _ = warped_pair(photo(), 512, (row, col) -> (20.0, -8.0))
# Brightness rising left to right, plus a weak vertical trend. Only the secondary image has it.
secondary = Float32[clean[row, col] * (0.4f0 + 1.2f0 * (col / 512)) + 0.3f0 * (row / 512)
                    for row in axes(clean, 1), col in axes(clean, 2)]

image_panels(reference, secondary; titles = ("reference", "secondary, gradient added"))

The true shift is dx = 20 pixels everywhere, so the error can be measured:

julia
settings = (; chip_size = 16, chip_size_max = 64, grid_spacing = 8)
_, grid = AutoRIFT.autorift_with_grid(reference, secondary; settings...)
truth = reshape([truth_dx[round(Int, grid.y[i]), round(Int, grid.x[i])] for i in eachindex(grid.x)],
                Base.size(autorift(reference, secondary; settings...).dx))
error_of(out) = filter(isfinite, abs.(out.dx .- truth))

for method in (:none, :highpass, :wallis, :sobel, :laplacian)
    out = autorift(reference, secondary; preprocess = method, settings...)
    err = error_of(out)
    println(rpad(string(method), 12),
            " measured ", lpad(AutoRIFT.nmeasured(out), 4),
            "   median correlation ",
            round(median(filter(isfinite, out.correlation)); digits = 3),
            "   median |error| ", round(median(err); digits = 3),
            "   p99 ", round(quantile(err, 0.99); digits = 2))
end
none         measured 2464   median correlation 0.842   median |error| 0.016   p99 0.11
highpass     measured 2469   median correlation 0.574   median |error| 0.0   p99 0.05
wallis       measured 2476   median correlation 0.527   median |error| 0.0   p99 0.03
sobel        measured 2451   median correlation 0.86   median |error| 0.016   p99 0.06
laplacian    measured 2465   median correlation 0.701   median |error| 0.016   p99 0.06

:none has a higher median correlation (0.842) than :highpass (0.574), :wallis (0.527) and :laplacian (0.701). Only :sobel (0.86) is higher. It also has the largest 99th percentile error, 0.11 px against 0.03 to 0.06 px for the filters, and a median error of 0.016 px against 0.0 for :highpass and :wallis.

Correlation therefore does not rank filters. Part of the unfiltered correlation comes from broad brightness structure common to both images, which says little about where small features moved. Filtering removes it and the coefficient falls. Compare filters by error against known motion, or, without a truth field, by the spatial coherence of the result.

What each filter does ​

Each panel below is the gradient-added secondary image after one filter, on its own grayscale because the outputs differ in scale:

julia
mask = trues(size(secondary))
methods = (("none", NoPreprocess()), ("highpass", Highpass()), ("wallis", Wallis()),
           ("sobel", Sobel()), ("laplacian", Laplacian()))

image_panels([first(AutoRIFT.preprocess(secondary, mask, m)) for (_, m) in methods]...;
             titles = first.(methods), size = (1700, 380), shared = false)

:none shows the gradient as the dominant structure in the frame. The filters differ in how much of the gradient's effect on contrast they remove. The ratio below is the standard deviation of the right third of the image over the left third:

julia
using Statistics: std
for (name, m) in methods
    f = first(AutoRIFT.preprocess(secondary, mask, m))
    left, right = std(@view f[:, 1:170]), std(@view f[:, 343:512])
    println(rpad(name, 11), " contrast right/left ", round(right / left; digits = 2))
end
none        contrast right/left 1.69
highpass    contrast right/left 2.01
wallis      contrast right/left 1.0
sobel       contrast right/left 1.87
laplacian   contrast right/left 1.08

The gradient multiplies the texture, so it makes the right side both brighter and higher in contrast. :highpass subtracts a local mean. That removes the brightness difference and leaves the contrast ratio at 2.0, above the unfiltered 1.7. :wallis also normalizes local variance and gives 1.0. :sobel keeps most of the trend (1.9). :laplacian gives 1.1 because it takes the logarithm first, which turns a multiplicative gradient into an additive one that the second derivative removes.

julia
none_out = autorift(reference, secondary; preprocess = :none, settings...)
high_out = autorift(reference, secondary; preprocess = :highpass, settings...)
field_panels(blank(none_out.dx, measured(none_out)), blank(high_out.dx, measured(high_out));
             titles = ("dx, preprocess = :none", "dx, preprocess = :highpass"))

Both fields show a uniform 20-pixel shift. The difference is in the tail of the error distribution, which a map does not show.

Filter width ​

Correlation and error also trade off with the width of Highpass:

julia
for width in (3, 5, 11, 21)
    out = autorift(reference, secondary; preprocess = Highpass(; width), settings...)
    err = error_of(out)
    println("width ", lpad(width, 2),
            "   median correlation ", round(median(filter(isfinite, out.correlation)); digits = 3),
            "   median |error| ", round(median(err); digits = 3),
            "   p99 ", round(quantile(err, 0.99); digits = 2))
end
width  3   median correlation 0.433   median |error| 0.0   p99 0.03
width  5   median correlation 0.574   median |error| 0.0   p99 0.05
width 11   median correlation 0.733   median |error| 0.016   p99 0.06
width 21   median correlation 0.813   median |error| 0.016   p99 0.06

Correlation rises with width, from 0.433 at 3 to 0.813 at 21, while the 99th percentile error doubles, from 0.03 to 0.06 px. A wider highpass passes more low-frequency content, so it moves toward :none in both respects. The default width of 5 has a 99th percentile error 0.02 px above the most accurate width here, which is 3.

Which filter for which imagery ​

filterwhat it doesreachuse for
NoPreprocessnothing; ZNCC alone0already-normalized imagery, or a baseline
Highpasssubtracts a windowed local mean2the default; optical imagery, most cases
Wallisnormalizes local mean and variance4scenes mixing high- and low-contrast ground, such as shadow beside snow
WallisGapfillWallis, filling interior gaps with matched noise37imagery with interior holes, such as Landsat 7 after the scan line corrector failure
Sobelsum of the x and y Sobel derivatives; directional, not a gradient magnitude2edge-dominated scenes; discards flat texture
Laplaciansecond derivative of the decibel image2radar amplitude
Decibel20 log10 of amplitude0SAR amplitude, whose dynamic range is multiplicative
Destriperejects banding in the Fourier domain-1Landsat 4 and 5 scan-direction banding
Derampremoves the linear phase ramp-1complex (SLC) input only

Decibel, Laplacian, Destripe and Deramp are tied to a data type. Decibel and Laplacian mask pixels whose amplitude is not positive. Deramp throws on real input, and the windowed amplitude filters throw on complex input. Destripe requires explicit along_track and cross_track keywords, the scan directions in degrees on the raster's grid.

The reach column, and why Deramp and Destripe cannot be blocked ​

AutoRIFT.filter_reach is how many pixels beyond a region must be read for the filter's output inside that region to match what filtering the whole scene would give. It is an upper bound. Blocked processing sizes its halo from it:

julia
for method in (NoPreprocess(), Highpass(), Highpass(; width = 21), Wallis(), Sobel(), Laplacian())
    println(rpad(string(method), 22), " reach ", AutoRIFT.filter_reach(method))
end
NoPreprocess()         reach 0
Highpass(5)            reach 2
Highpass(21)           reach 10
Wallis(5, 0.0)         reach 4
Sobel(5)               reach 2
Laplacian(5)           reach 2

Reach is not the window's half-width. WallisGapfill's 37 comes from its fill decisions, which depend on how far the nearest real data lies, and no window bounds that.

Deramp and Destripe return -1, meaning no finite reach. Each estimates from the whole image, so no halo can reproduce the result. Check the sign before using a reach as a width. AutoRIFT.halo throws on a negative reach rather than returning a halo shorter than the correlation alone. Neither filter can be combined with process_block_size; apply it to the whole scene yourself before blocking.

Filtering is reused across pairs in a cache ​

Both images get the same filter. A AutoRIFT.Cache keeps the filtered result of each image, and reinit! reuses it for an image that is already in either slot, so a time series filters each acquisition once. See Correlating many pairs. A run with process_block_size filters each block from the raw input during the run instead.
