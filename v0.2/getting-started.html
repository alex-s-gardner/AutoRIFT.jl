Getting started ​

Install ​

julia
using Pkg
Pkg.add(url = "https://github.com/alex-s-gardner/AutoRIFT.jl")

AutoRIFT.jl is not in the General registry; install it from its repository.

Correlating arrays needs nothing further. Optional packages add input types and features. Load them with using; installing AutoRIFT does not install them.

load thisto get
Rasters + ArchGDALgeospatial input, velocities in map units
DimensionalDatalabeled-array input, offsets in pixels
DiskArrayschunked on-disk arrays (Zarr, NetCDF, HDF5) read by window
ImageFeaturessparse first guesses from ORB features
AkazeFeaturessparse first guesses from A-KAZE features; install with Pkg.add(url = "https://github.com/nlw0/AkazeFeatures.jl")
NearestNeighborsk-d tree neighbor search in the first-guess consistency filter
ImagePairGeometrysearch grids from a geogrid PairGeometry; install with Pkg.add(url = "https://github.com/alex-s-gardner/ImagePairGeometry.jl")
MetalApple GPU backend (experimental)

One correlation ​

You need two images of the same scene, on the same grid, differing by motion. This page uses a photograph and a warped copy of it, so the applied displacement is known:

julia
using AutoRIFT
include("../figures.jl")  # plotting helpers and the example scenes; see [Plotting](@ref)

# Sideways motion that is fastest in the middle rows and slower toward the top and bottom edges,
# with a 2 px downward drift. Ice in a valley moves like this.
flow(row, col) = (4.0 + 16.0 * sin(pi * row / 512), -2.0)

reference, secondary, true_dx, true_dy = warped_pair(photo(), 512, flow)

image_panels(reference, secondary)

The third panel overlays the two images, the reference in magenta and the secondary in green. Where nothing moved the overlay is gray; a feature that moved shows twice, magenta where it was and green where it went. The displacement varies with row: 4 px at the top and bottom edges, 20 px in the middle rows. One number for the whole frame cannot describe it. The applied field, which the result below should reproduce:

julia
field_panels(true_dx, true_dy; titles = ("true dx (px)", "true dy (px)"))

Read the result ​

out holds several layers with one value per grid point. The first three to use:

julia
displacement_panels(out)

  • dx — displacement along the second index (columns), in pixels

  • dy — displacement along the first index (rows), positive downward

  • correlation — the correlation coefficient at the peak; higher is a better match

julia
(measured = AutoRIFT.nmeasured(out), of_total = length(out.dx))
(measured = 121, of_total = 121)

Points that could not be measured are NaN, not zero, because zero is a valid displacement. Filter before reducing:

julia
using Statistics: median
(median_dx = median(filter(isfinite, out.dx)), median_dy = median(filter(isfinite, out.dy)))
(median_dx = 17.53125f0, median_dy = -2.0f0)

dy is −2, the value applied to the whole scene. dx runs from about 4 at the top and bottom edges to 20 in the middle rows, so its median describes no part of the scene. Compare the dx panel against the true field instead.

The grid is 11×11 points by default, coarser than the 512×512 input, so the panels look blocky. grid_spacing sets it; A guided walkthrough shows its effect.

The sign is the offset, not the motion

dx/dy point from the secondary image back to the reference, the opposite of how the features moved. A feature that moved six columns left reports dx = +6. The convention comes from the reference implementation; see Conventions.

Judge it before using it ​

Filter on correlation before using the points:

julia
good = out.correlation .> 0.3
(kept = count(good), rejected = AutoRIFT.nmeasured(out) - count(good))
(kept = 109, rejected = 12)
julia
quality_panels(out)

By default autorift also rejects spatial outliers, so points that disagree with their neighbors are already removed. Judging a result covers the threshold and why to filter on correlation rather than peak_ratio.
