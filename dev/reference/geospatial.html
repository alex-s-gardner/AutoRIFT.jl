Geospatial ​

Loading Rasters adds an autorift method that reads the pixel size and coordinate reference system from the inputs and returns map-oriented feature motion rather than pixel offsets. Loading DimensionalData alone adds the same dimension handling without a CRS.

The core autorift is documented on Correlating; this page documents the methods these packages add. Each section resolves its names in the extension module that defines them.

Rasters ​

AutoRIFTRastersExt.AutoRIFTRastersExt Module
julia
AutoRIFTRastersExt

Accept Raster input and return a RasterStack carrying the output grid's coordinates, CRS and per-layer missingval.

A Raster is an AbstractDimArray, so grid alignment checking and output-dimension construction come from AutoRIFTDimensionalDataExt. This extension adds CRS validation between the two inputs, the y-orientation correction, and conversion from pixel offsets to velocity.

Y orientation

A north-up GeoTIFF stores y decreasing (the first row is the northernmost) and a south-up file stores it increasing. The same scene written both ways gives dy of opposite sign from the core. This extension reads the direction of the row lookup and corrects it, so both storage orders give the same field.

vx/vy, not dx/dy

The names record two conversions from the core's output:

  • Orientation: dy becomes north-positive rather than row-positive.

  • Sign: the core reports the offset from secondary back to reference, the negative of ground motion. Here the result is feature motion: +vx east, +vy north.

To get the unconverted pixel offsets, correlate parent(raster) directly.

AutoRIFT.autorift Method
julia
autorift(reference::AbstractRaster, secondary::AbstractRaster; dt = nothing, kwargs...)

Correlate two rasters, returning a RasterStack on the output grid.

Layers are vx, vy, correlation, peak_ratio, chip_size and interpolated, each with its own missingval. The output grid has the inputs' CRS and axis order, at grid_spacing times their pixel size. Throws ArgumentError if the inputs have different CRSs.

Keywords

All of AutoRIFT.params's, plus:

  • dt = nothing: the interval between acquisitions. nothing leaves vx and vy in pixels. A Dates.Period such as Day(16), or a Real number of years, converts them to CRS units per year (meters per year for a projected raster). Year and Month throw, having no fixed length.

  • reference_valid, secondary_valid: per-pixel validity masks, as arrays or rasters.

  • process_block_size: (X, Y) pixels per block. Default: for file-backed input, a size derived from the halo and rounded up to the rasters' chunking; for input in memory, nothing (one block).

  • cache_budget = :auto: bytes of file-backed imagery the run may hold in memory, or nothing to read a window per block per pass. See AutoRIFT.autorift.

julia
using AutoRIFT, Rasters, ArchGDAL, Dates
out = autorift(Raster("early.tif"), Raster("late.tif"); grid_spacing = 32, dt = Day(16))
out.vx, out.vy, out.correlation

ArchGDAL must be loaded to open a file.

With lazy = true the correlation reads from the file rather than materializing it. Such a run is blocked, so the filtered Float32 scene is never formed, and a raster's missingval is turned into a validity mask. The result is bit-identical to the same pair in memory. See Correlating scenes larger than memory.

Sign convention

vx and vy are feature motion in map orientation: +vx east, +vy north. A north-up and a south-up raster of one scene give the same answer.

Velocity is exact only for an axis-aligned grid

dt scales by the lookup's pixel size, which assumes displacement along a pixel axis is displacement along a map axis. That holds for a north-up projected raster, including essentially all Landsat and Sentinel-2 optical imagery. It does not hold for a rotated grid or for radar geometry. Pass dt = nothing in those cases and convert the pixel offsets separately.

DimensionalData ​

AutoRIFTDimensionalDataExt.AutoRIFTDimensionalDataExt Module
julia
AutoRIFTDimensionalDataExt

Accept AbstractDimArray input and return a DimStack whose dimensions describe the output grid.

The extension reads coordinates from the input lookups, calls the plain-array core, and rebuilds the result as a stack on the output grid.

It handles dimensional arrays without a CRS, such as radar range-Doppler data, whose dimensions need not be X and Y (Dim{:range} and Dim{:azimuth} are typical). The first dimension is rows and the second is columns. With no CRS there is no map orientation, so it reports the core's dx and dy unchanged: pixel offsets from secondary back to reference, dy increasing with row index. The Rasters extension converts these to feature motion.

source
AutoRIFT.autorift Method
julia
autorift(reference::AbstractDimArray, secondary::AbstractDimArray; kwargs...) -> DimStack

Correlate two dimensional arrays, returning a stack on the output grid.

Layers are dx, dy (pixels), correlation, peak_ratio, chip_size and interpolated; see AutoRIFT.MultichipResult. Accepts the keywords of AutoRIFT.params, plus reference_valid and secondary_valid (per-pixel validity masks, arrays or dimensional arrays) and the blocking keywords of AutoRIFT.autorift. Throws ArgumentError unless both inputs are 2-D, and DimensionMismatch unless their dimension names and lookups are equal.

The first dimension is rows and the second is columns. For a projected raster, load Rasters for map-oriented vx and vy.

Sign convention

dx and dy are pixel offsets from secondary back to reference, the negative of feature motion, with dy increasing along the first dimension.
